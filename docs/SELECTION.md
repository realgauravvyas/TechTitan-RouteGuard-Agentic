# Why Problem 6

This is an implementation-risk assessment, not a statistical prediction of qualifying or winning. We do not know competitor submissions or judge preferences beyond the published rubric.

| Problem | End-to-end feasibility | Main submission risk |
|---|---|---|
| 1 Clinical documentation | Synthetic records explicitly allowed | Clinical consistency and validation need defensible domain rules |
| 2 Emergency triage | Synthetic cases possible | Safety/risk scoring and adaptive clinical questioning |
| 3 Learning planner | Fully simulatable | Easy to resemble a timetable generator; learning improvement unproven |
| 4 Assignment tutor | Public or generated exercises | Reliable multimodal parsing and adaptive tutoring verification |
| 5 Customer resolution | Excellent simulator fit | Strong alternate choice; differentiate beyond common support demos |
| **6 Supply-chain recovery** | **Excellent simulator and optimization fit** | **Keep assumptions explicit; prove stateful recovery and constraints** |
| 7 Fantasy sports | Simulation permitted | Sports scoring/context realism and licensing/provenance |
| 8 Athlete planner | Synthetic inputs expected | Defensible workload rules without unsupported health claims |
| 9 SOC investigation | Sandbox possible | Credible correlated security evidence and outcome attribution |
| 10 IAM mitigator | Strong technical alternate | Faithful permission/dependency simulation is harder to explain quickly |
| 11 Application agent | Uses genuine profile evidence | Needs complete candidate evidence; no fabrication permitted |

Problem 6 lets us implement every required deliverable with owned synthetic data, expose real mutations, inject multiple failures and verify the final constraints numerically. Its strength comes from demonstrable evidence, not from having more agents or a particular framework.

## Rubric coverage

| Criterion | Weight | Evidence in RouteGuard |
|---|---:|---|
| Agentic workflow and autonomy | 25% | Goal, observations, search, actions, feedback-dependent tool selection |
| Tool/environment interaction | 15% | Catalog lookup, optimizer, atomic reservations, cancellation/refund, state verifier |
| Adaptation and failure recovery | 15% | Pre-commit stale plan; post-commit outage; residual replanning |
| Technical implementation | 15% | Standard-library app, SQLite transactions, exact optimizer, restart recovery |
| Problem relevance and innovation | 10% | Minimal-change recovery preserves unaffected commitments; auditable evidence |
| Prototype functionality and UX | 10% | Working console, custom constraints, live outage injection, export |
| Evaluation, verification and robustness | 10% | 17 tests, 80 oracle comparisons, 10 runtime checks |

## What we deliberately do not claim

No guaranteed qualification, measured business savings, production readiness, live supplier integration, foundation model, or proven generalization to multi-SKU logistics. An LLM explanation layer could be added later, but the current submitted agent is transparently symbolic and its actions are determined by observable state and constrained search.
