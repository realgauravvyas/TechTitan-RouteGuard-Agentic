# Synthetic data card

Owner: TechTitan. Created for the IIT Bhubaneswar Round 1 prototype. No external customer, order, medical, financial-account or personal dataset is used.

## Sources and generation

- Default scenario data is authored in `engine.initial_world`.
- 80 benchmark cases are generated by Python's `random.Random(1742838)` in `evaluate.py`.
- Geographic names make the demo easy to understand locally; all providers and values are fictional.
- The official problem statement explicitly asks for a simulated logistics environment. Synthetic data is therefore suitable for the submitted scope.

All costs are total modeled incremental recovery costs per lot. Carbon is a supplied scenario attribute, not calculated from real distances or an emissions standard. Budget/carbon accounting includes active reservations; pre-dispatch cancelled reservations are fully reversed.

## Evaluation distribution

Demand: 40/60/80/100 units. Budget: INR 4,500–16,000 in increments of 500. Carbon: 25–120 kg in increments of 5. Deadline: 8/12/18/24 h. Each offer has 20/40/60/80 stock units, about 80% independent availability, lot cost 700–1,600 in increments of 50, carbon 2–15 kg and ETA 5/8/12/18/22/30 h. Cases are deliberately mixed in difficulty; they are not sampled from an industry distribution. No training/test split is applicable because no model is trained.

## Limits to interpretation

31/80 generated cases are feasible. Success rate over all 80 would conflate impossible goals with agent failures. Report 31/31 verified feasible cases and 49/49 correct infeasibility decisions separately. The baseline is cheapest-first without global carbon search and without recovery; it is not a tuned enterprise optimizer. Zero constraint violations in this suite is evidence only for the tested sandbox.
